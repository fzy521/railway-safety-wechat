## 修复云函数调用错误

### 问题分析

1. **错误现象**：事故管理页面出现 `[FUNCTION_NOT_FOUND] FunctionName parameter could not be found` 错误
2. **根本原因**：在 `emergency.ts` 文件中，`callCloudFunction` 函数的调用方式错误
3. **错误代码**：

   ```typescript
   await callCloudFunction({
     name: 'emergency-plan-management',
     data: { action: 'list', ...params }
   })
   ```
4. **正确调用方式**：

   ```typescript
   await callCloudFunction('emergency-plan-management', { action: 'list', ...params })
   ```
5. **影响范围**：所有使用 `emergency-plan-management` 云函数的操作都会失败

### 修复计划

1. **修复 emergency.ts 中的云函数调用**：

   * 文件：`web-admin/frontend/src/api/emergency.ts`

   * 修复所有 `callCloudFunction` 调用，将对象参数改为两个独立参数

   * 修复函数：`getEmergencyPlans`、`getEmergencyPlanDetail`、`createEmergencyPlan`、`updateEmergencyPlan`、`deleteEmergencyPlan`、`uploadPdfFile`、`deletePdfFile`

2. **验证修复效果**：

   * 确保事故管理页面不再出现 FUNCTION\_NOT\_FOUND 错误

   * 验证应急管理页面的应急预案列表、详情、创建等功能正常工作

### 修复步骤

1. 打开 `web-admin/frontend/src/api/emergency.ts` 文件
2. 修改所有 `callCloudFunction` 调用，将 `{ name: 'xxx', data: yyy }` 改为 `'xxx', yyy`
3. 保存文件
4. 刷新页面，验证错误是否消失
5. 测试相关功能，确保正常工作

### 预期效果

* 事故管理页面的统计数据和列表正常加载

* 应急管理页面的应急预案功能正常工作

* 所有云函数调用都能正确执行，不再出现 FUNCTION\_NOT\_FOUND 错误
